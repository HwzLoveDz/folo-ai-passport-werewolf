# AI-PASSPORT Werewolf 三键交互规范

本文是 `UP`、`DOWN`、`OK` 三个实体按键的统一交互合同。UI 页面、控制器动作和页脚提示必须保持一致；不得在单个页面为同一手势临时创造相反含义。

## 全局规则

| 输入 | 唯一语义 |
|---|---|
| 短按 `UP/DOWN` | 移动焦点、切换选项或改变当前值 |
| 短按 `OK` | 执行当前焦点项：选择、`WAIT/READY`、继续或重试；私密页至少成功查看一次后用于显式提交 `DONE`；玩家详情的显式红色 `KICK PLAYER` 是唯一危险例外 |
| 长按 `OK` | 只用于确认界面已明确告知的重要/不可逆动作，或按住显示私密信息 |
| 长按 `DOWN` | `BACK / CANCEL / EXIT REQUEST`：返回上一层、取消当前复核，或请求退出当前会话 |
| 松开 `OK` | 只在私密页承担语义：立即清除私密内容并封屏，不提交“已查看” |
| 长按 `UP` | 不使用，保留 |
| 双击 | 不定义、不注册、不作为隐藏操作 |

长按 `DOWN` 不得直接踢人或关闭房间。单人踢出只允许从目标玩家详情的显式红色
`KICK PLAYER` 项发起：菜单默认停在 `BACK`，选中危险项后短按 `OK` 直接执行，
不再增加二次确认。关闭整个房间仍必须进入带 `BACK` 的确认菜单。`ONLINE` 客机
离房是明确例外：长按 `DOWN` 直接发起可靠离房请求，不再显示第二层弹窗，也不
立即拆除链路；输入保持锁定，直到收到 ACK 或到达有界截止时间。

## 事件处理优先级

按键事件必须按以下顺序解释：

1. 私密页的 `OK RELEASE` 最高优先，无论断线、换页、模型更新或队列繁忙，都必须先清除内容并封屏。
2. 扫描/配对取消，以及客机大厅处于 `ONLINE` 时的长按 `DOWN` 离房，先于普通输入锁
   解释；`RECONNECTING` 当前仍锁定输入并等待恢复或有界 host-loss。终止流程开始后，
   除私密松开外不再接受输入。
3. 有弹窗时只由弹窗处理输入，不得把同一事件透传给背后页面。
4. 处理长按 `DOWN` 的返回、取消或退出请求。
5. 最后才按当前页面处理短按导航和 `OK` 主动作。

一次物理按键序列最多产生一个业务动作。已触发 `OK LONG` 后，松手及其尾随
`OK CLICK` 都不得提交 `ROLE_SEEN`、`ACK_RESULT` 或其他业务动作；完成确认必须来自
随后一次全新的短按 `OK`，当前 UI 已显式抑制该尾随事件。`DOWN LONG` 的尾随事件也
必须保持无害，但目前仍需按键库边沿测试和真机验收；在取得证据前不得标记为已验证。

## 逐页映射

### 模式选择

- 短按 `UP/DOWN`：在 `CREATE ROOM` 和 `JOIN ROOM` 之间移动。
- 短按 `OK`：进入选中模式。
- 本页是根页，长按 `DOWN` 无动作。

### 房间列表

- 短按 `UP/DOWN`：选择房间。
- 短按 `OK`：加入选中房间。
- 长按 `DOWN`：返回模式选择页。

### 扫描与配对中

- 普通输入锁定。
- 长按 `DOWN`：取消本次连接并返回；该动作不得改变到另一个广播房间。

### 大厅：普通玩家

- 玩家列表徽标统一为：`H` 是房主，`Y` 是当前客机自己的行，`G` 是其他客机。徽标和昵称都不是认证信息。
- `ROOM` 信息下显示本机与房主链路的六位只读 `VERIFY` 码；没有选择、确认或已确认状态。
- 短按 `OK`：只切换本机 `WAIT/READY`。
- 连接为 `ONLINE` 时长按 `DOWN`：直接发起可靠离房请求，不显示离房弹窗；等待 ACK
  或截止时间期间锁定输入。`RECONNECTING` 时当前不接受主动退出，只等待恢复或进入
  有界的 host-loss 错误流程；这项限制仍列在路线图中等待产品决策。
- 任何其他玩家的状态都不可由本机修改。

### 大厅：房主

- 短按 `UP/DOWN`：遍历所有已加入玩家，包括房主自己。
- 焦点在某位客机时，短按 `OK`：进入该客机详情；详情显示房主与该客机链路的六位只读 `VERIFY` 码，不得记录人工比对结果。
- 焦点在房主自己时，短按 `OK`：切换房主的 `WAIT/READY`。
- 客机详情是 `BACK / KICK PLAYER` 两项菜单，默认选中 `BACK`；短按 `UP/DOWN` 切换，短按 `OK` 执行当前项。`BACK` 返回列表，`KICK PLAYER` 直接对冻结的目标发起可靠踢出，不再出现第二层确认；长按 `DOWN` 也始终返回列表。
- 满足开局条件时，长按 `OK`：开始游戏，不依赖当前焦点行。v5 条件是 7 个座位已占用、7 份资料已同步、7 人 `READY`，且 6 条房主到客机的加密链路均已建立。
- 在房主大厅列表长按 `DOWN`：打开 `CLOSE ROOM?` 警告，默认选中 `BACK`。
- 房主可以聚焦自己的行并切换自己的 `WAIT/READY`，但自己的行不能进入玩家管理，
  也绝不能被踢出；客机离开时若它正被选中，焦点回到房主自己，不得自动改成
  另一位客机。

### 玩家详情与关房警告

- 所有包含可选菜单的弹层都必须明确提供并默认选中 `BACK`。
- 玩家详情：短按 `UP/DOWN` 在 `BACK` 与红色 `KICK PLAYER` 间切换，短按 `OK` 执行当前项；踢出开始后锁定输入并等待 ACK 或有界超时。
- `CLOSE ROOM?`：短按 `UP/DOWN` 在 `BACK` 与红色 `CLOSE ROOM` 间切换；焦点在 `BACK` 时短按 `OK` 返回大厅，焦点在危险项时短按 `OK` 无动作、长按 `OK` 才关闭整个房间。
- 长按 `DOWN`：只要动作尚未发出，就无条件返回或取消。
- 玩家详情打开时必须冻结目标座位；可靠踢出还必须冻结其会话代次，不得因大厅刷新而改变目标。
- `ROOM CLOSED`、`REMOVED FROM ROOM` 是终止后的通知，不是可返回原状态的菜单，因此保留唯一 `OK` 返回主界面；发送中/等待 ACK 弹层不提供可打断选项。

### 私密角色与预言家结果

- `OK PRESS`：记录当前私密页和私密 gate epoch，但不显示内容。
- `OK LONG`：只有按下时记录的页面和 epoch 仍匹配时才显示，并将当前 gate 标记为“至少成功查看过一次”。
- `OK RELEASE`：立即清除私密字符串并封屏，不提交业务动作。只要尚未显式完成，玩家可重复长按揭示、松手封屏，次数不受限制。
- 成功查看过至少一次后，另起一次短按 `OK` 才提交当前 gate 的 `ROLE_SEEN` 或 `ACK_RESULT`。未查看时短按无动作；长按序列尾随的 `CLICK` 必须被抑制，不能冒充这次独立短按。
- 提交后锁定普通输入，等待权威状态推进或确认；不得把同一次提交应用到新的私密页或 gate epoch。
- 其他按键全部忽略。

### 夜间目标与秘密投票

- 短按 `UP/DOWN`：选择合法目标。
- 短按 `OK`：进入目标复核，不提交。
- 复核中长按 `OK`：提交冻结的目标。
- 复核中长按 `DOWN`：取消复核并回到目标列表。
- 页脚必须明确区分 `OK REVIEW` 和 `HOLD OK CONFIRM`。

### 发言

- 只有当前发言者可长按 `OK` 提前结束发言。
- 其他玩家的输入锁定。

### 天亮、出局与其他公开结果

- 短按 `OK`：确认并继续。
- 确认发出后锁定输入，直到权威状态推进或重新打开。

### 终局、被踢与房间已关闭

- 这些状态已无未提交的局内操作。
- 房主进入终局后可能短暂显示 `DELIVERING REVIEW / WAIT`；只有终局状态与完整牌组的
  可靠发送队列清空后才开放退出，等待期间普通输入锁定。
- 短按 `OK`：返回模式选择页。
- 其他按键忽略。

### 错误页

- 可恢复时，短按 `OK`：重试。
- 长按 `DOWN`：退出错误页并回到模式选择页。若活动 peer 需要通知，控制器必须在
  进入错误页前先完成相应的可靠终止；错误页本身不再发起离房。
- 不可恢复错误不为短按 `OK` 绑定动作。

### 发送、等待 ACK 与重连

- 所有普通输入锁定，页脚使用 `WAIT` 或 `INPUT LOCKED`，不得显示无法执行的按键提示。
- 私密页上的 `OK RELEASE` 仍必须立即清除内容并封屏，但不得由此提交确认。
- 当前实现有一个尚未关闭的显示缺口：客机大厅和私密页在 `RECONNECTING` 时可能仍
  保留普通操作页脚，虽然处理器会拒绝这些按键。该页脚必须以连接状态为准视为不可
  执行，并已在 [ROADMAP.md](ROADMAP.md) 登记修复与预览门槛。

## 实现与验收不变量

- `WAIT/READY` 只能修改本机状态；房主不能替客机准备。
- 房主只能踢出客机，不能踢自己。
- 单人踢出只从默认焦点为 `BACK` 的目标详情执行，选中红色 `KICK PLAYER` 后短按
  `OK` 直接发起；房主关房仍须在带 `BACK` 的警告中选中危险项并长按 `OK`。客机
  在扫描、配对或 `ONLINE` 大厅中的取消/可靠离房是长按 `DOWN` 的直接例外。
- `H`/`Y`/`G` 和昵称只用于显示，不参与权限、安全或开局判断。
- `VERIFY` 码只供当面比对：本地派生、不在包中传输、不提供按键确认，也不参与 `READY` 或开局门禁；不一致时由客机离房或房主踢人。
- 页脚只显示当前状态真正可执行的操作，常规页面统一使用 `UP/DN`、`OK`、
  `HOLD OK` 和 `HOLD DN`；私密页为准确表达物理边沿，可使用 `PRESS + HOLD OK`、
  `RELEASE OK`、`REVIEW` 和 `DONE`。
- 快速点按、超时长按、按住时断线、弹窗中刷新大厅及动作队列满时，都必须保持上述语义。
- 私密查看状态绑定当前页面和 gate epoch：换页、epoch 变化、断线或输入失效必须立即封屏并清除待提交资格；同一 gate 的普通 heartbeat 不得打断有效长按或已经取得的重复查看资格。
- 模拟器只证明生产 UI 的状态和事件映射；长按时间、ADC 按键边沿和真机误触仍需实机验收。
