# AI-PASSPORT 狼人杀开发路线

本文是项目进度的唯一事实源；规则语义以 [MVP_RULES.md](MVP_RULES.md) 为准，按键
语义以 [CONTROLS.md](CONTROLS.md) 为准，协议实现边界以
[ARCHITECTURE.md](ARCHITECTURE.md) 为准。

## 难度判断

整体难度为中高。7 人规则本身适合用确定性状态机实现，主要风险不在“发牌和投票”，
而在以下四件事必须同时成立：

1. 七台设备在丢包、重复包和乱序下仍只推进一次状态。
2. 角色、狼队友、夜间目标、投票和查验结果不能进入广播或串口日志。
3. 没有预置生产密钥时，commit/reveal 仍要阻止参与方在看到对端 reveal 后替换本端
   材料；物理链路两端是否是预期玩家，则依赖双方实际比较只读 `VERIFY` 码。
4. 三键设备上，私密查看、长按确认、平票答辩和异常退出不能让玩家误操作。

因此首版固定为 7 人单一规则，不同时加入警长、女巫、猎人、语音识别或主机迁移。

## 分阶段交付

### P0：规则与产品边界

- [x] 固定 `2 狼 + 预言家 + 守卫 + 3 平民`。
- [x] 明确狼刀分歧重选、守卫不能连续守同一人、平票答辩与一次复投。
- [x] AI 只做可选旁白，不参与规则裁决。
- [x] 明确首版不支持主机迁移和重启续局。

### P1：可验证的软件纵向切片

- [x] 独立的确定性 C 规则状态机和主机测试。
- [x] 固定长度、显式字节序的消息与帧编解码。
- [x] ACK、有限重试、重放窗口、动作幂等和 peer generation。
- [x] X25519 承诺/揭示配对、独立 LMK 与六位人工核验码。
- [x] 建房、加入、准备、发牌、夜晚、白天、投票、终局 UI 控制器。
- [x] ESP-IDF 5.5.3 全量构建和镜像尺寸复核。

### P2：实体设备验收

> 已取得的部分证据：多轮单机/双机测试已跑通建房、加入、准备、只读 `VERIFY`、
> 定向踢出和退房主流程。它不能关闭下列三机、七机、资源余量或空口审计门槛；
> 最新私密重复查看修订仍需重新上板确认。

- [ ] 单机：启动、按键边沿（含 `DOWN LONG` 尾随事件）、长按/松手遮挡、堆栈和
  内部 RAM 余量。
- [ ] 三机：发现与配对、核验码、丢包/重试、退出重入、主机失联。
- [ ] 重连交互：当前 `RECONNECTING` 锁定输入，但客机大厅/私密页可能仍残留不可执行
  的普通操作页脚；决定是否允许长按 `DOWN` 主动退出，并在 UI 预览后补齐状态机、
  锁定提示和实机回归。
- [ ] 七机：完整跑局、所有角色、两类平票、两种胜负和长时间稳定性。
- [ ] 串口与空口审计：秘密不进日志，游戏数据不进广播。

### P3：体验完善

- [ ] 自动倒计时和明确的超时裁决规则。
- [x] 本地非阻塞提示音与隐私静音策略；实体桌面音量和七机声学一致性仍归 P2 验收。
- [ ] 可选 AI 旁白；断网或生成失败时必须自动回退，不阻塞规则状态机。
- [x] 面向玩家的快速上手说明书：[中文](PLAYER_GUIDE.md) / [English](PLAYER_GUIDE.en.md)。
- [ ] 设备内新手引导、重开流程和实体多人可用性测试。

### P4：多游戏平台化

- [ ] 将房间、配对、可靠传输和通用三键选择抽成稳定平台接口。
- [ ] 第二个低秘密依赖游戏验证抽象，避免为狼人杀过早设计通用框架。
- [ ] 规则包版本协商、资源预算和兼容性测试。

## 公开发布前的文档与复现门槛

以下事项不阻塞当前私有仓库开发，但在公开发布前必须关闭；未确认授权时不能靠猜测
补许可证：

- [ ] 选择项目根许可证，并补充第三方声明。
- [ ] 为移植的 BSP 代码记录上游 URL、精确 commit、原许可证、修改内容和适用板卡版本。
- [ ] 固定 ESP Component Manager 直接依赖版本，或提交经审核的依赖锁文件，避免新克隆
  随时间解析到不同版本。

## 首版验收原则

只有 P1 构建通过且 P2 的七机实测完成，才可以称为“狼人杀首版可交付”。主机测试或
单台开机都不能替代无线环境与多人真实操作证据。
